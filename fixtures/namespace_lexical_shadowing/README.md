# Lexical metadata compiler probes

Compiler and generated-consumer evidence for
[#152](https://github.com/dustcodegen/dust/issues/152).
The standalone reflection probes require no packages.

`annotations.dart` deliberately defines unrelated local annotations. These do not
stand in for Dust package provenance in the Rust regressions: the resolver test
reads the real Dust HTTP annotation declaration source, and the driver test uses
the existing namespace workspace harness.

`traditional.dart` checks constructor, field, method and parameter metadata.
Reflection asserts identity with the class constant, not just compilation.
`primary.dart` checks a primary class's method/parameter metadata. Both retain a
real imported annotation on the outer class, where the member does not shadow it.

Run with an explicitly selected SDK executable:

```sh
"$DART_MIN" analyze fixtures/namespace_lexical_shadowing/traditional.dart
"$DART_MIN" --enable-asserts fixtures/namespace_lexical_shadowing/traditional.dart
"$DART_LATEST" analyze fixtures/namespace_lexical_shadowing
"$DART_LATEST" --enable-asserts fixtures/namespace_lexical_shadowing/traditional.dart
"$DART_LATEST" --enable-asserts fixtures/namespace_lexical_shadowing/primary.dart
```

Verified locally on Dart 3.6.0 and 3.13.5; the primary probe requires Dart 3.13.
The two associated Rust regressions now pass with the approved
[structured use-site scopes](../../docs/design/annotation-lexical-scopes.md):

```sh
cargo test -p dust_resolver --test namespace_graph class_constant_metadata_cannot_become_an_imported_client_verb
cargo test -p dust_driver --test driver_tests class_constant_metadata_shadows_an_import_prefix
```

These VM-only reflection probes are not Flutter, server generation, constant
evaluation or complete lexical-scope acceptance evidence. No remote CI is needed.

## Fresh generated usage

`generated_traditional.dart.snapshot` and `generated_primary.dart.snapshot` are
source inputs staged by `scripts/sdk_lexical_scopes.py` through the existing local
`scripts/sdk_compat.py` minimum/latest gate. They import the real Dust annotation
package. `@dust.Derive([dust.ToString()])` on the class sees the import; bare
`@dust` on its constructor, fields/header, method and parameters sees the class's
foreign constant. The primary constructor's documented `this;` is needed only to
document/annotate that constructor, not to enable generation.

The helper builds and checks fresh output, analyzes source and generated code
with strict types and enabled lints, runs `runtime_test.dart.snapshot` using
`package:test`, and requires all generated executable lines to be hit without
honoring coverage-ignore comments. The full generated bytes must match
`generated.dart.snapshot` on all three Dart targets. Staged source/output/test
files and analyzer settings are restored on both success and failure.

Use direct real Dust annotations with their arguments. Constants containing actual
Dust annotations, opaque initializer expressions and constant cycles currently
fail clearly instead of dropping arguments or falling back across a known shadow.
These host-Dart probes do not claim Flutter-engine or server-generation proof.
