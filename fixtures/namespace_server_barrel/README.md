# Public server-entrypoint namespace control

This fixture exercises the production source loader before server registration.
`dust_dart` owns `ToString`, but the actual `dust_server` annotations must remain
foreign to the current default client catalog. They must not acquire Dio meaning
merely because their short names overlap.

The driver regression copies actual runtime source trees into an owned temporary
workspace and resolves `package:dust_server/server.dart` through package config.
Its SDK and external dependency namespaces are synthetic, so it is not compiler
evidence. A source-loader unit contract checks both foreign ownership before
server claims and exact server ownership after explicit test-only claims, then
checks resolved configs never acquire Dio normalization. Command tests compare exact
ordinary-model generated bytes, warm/check behavior, then removes an actual
barrel/declaration source and checks failed-build/cache preservation and recovery.

Independent consumers using actual package resolution and SDK sources pass on
Dart 3.6.0 and 3.13.5: copy the snapshot to `lib/model.dart` in an owned package
depending on the local `dust_dart` and `dust_server`, then run fresh
`dust build --clean`, `dust check`, `dart analyze --fatal-infos` with standard
lints/strict casts/inference/raw types, and `dart --enable-asserts lib/model.dart`.
No pre-existing part or placeholder mixin supplies the positive generation proof.

This is not server handler generation, server-owned default registration, or
full phase-0 acceptance. Those remain gated by #84/#114 and the server design.
