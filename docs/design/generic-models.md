# Generic model generation

Status: **approved design; implementation in progress**. Tracks [#93](https://github.com/dustcodegen/dust/issues/93)
under primary-constructor work [#76](https://github.com/dustcodegen/dust/issues/76)
and parser migration [#68](https://github.com/dustcodegen/dust/issues/68).

Grammar acceptance is not generator support. The draft now generates typed
`CopyWith` helpers for the scoped traditional and primary consumers below.
Scoped core-name/local collisions and generic validation helpers are covered,
but generated-member collisions and integration capability checks remain unfinished.
Do not use this draft as production guidance.

## Approved decision

Retain structured class type-parameter/bound facts and applied-mixin facts,
then generate parameterized mixins and helpers. A generic model explicitly
passes its type arguments to its generated mixin:

```dart
@Derive([CopyWith(), ToString()])
class const Box<T>(final T value) with _$Box<T>;

final Box<int> updated = Box<int>(1).copyWith(value: 2);
```

This usage is exercised by generated consumers in the draft. An
equivalent traditional class uses the same `with _$Box<T>` spelling.
Non-generic classes retain `with _$Box`, their current APIs and generated bytes.
No SDK floor, version, dependency or workflow change is proposed.

A generic class omitting or misapplying its generated mixin arguments must get
a source-located Dust diagnostic. Do not silently instantiate the mixin to its
bounds and erase the model's chosen type arguments. Validation needs written
mixin facts; checking the source with a plugin-local string parser is not an
acceptable substitute.

## Why this option

Local handwritten language prototypes compared three approaches:

| Approach | Result | Decision |
| :--- | :--- | :--- |
| Parameterized mixin, `with _$Box<T>` | Preserves `Box<int>`, typed replacements and real instance dispatch. | Recommended. |
| Raw or erased mixin | A copy of `Box<int>` widens to the bound, e.g. `Box<num>`; the erased prototype accepts a `double`. | Reject as a silent compatibility fix. |
| Generic extension for copying | Static calls work, but `dynamic` receivers cannot invoke extension-only members. Extensions cannot override `Object.toString`. | Not a drop-in replacement for the existing mixin API. |

The extension alternative would also require a visible extension surface and
resolution/collision policy. It is not the smaller complete implementation of
Dust's existing instance-member contract.

## Preserve structured facts

The listed grammar exposes class `type_parameters` and
`type_parameter` / `type_bound` nodes. The initial implementation discarded them;
the draft now retains these facts through class IR.

Required facts:

- Parsed class parameters in declaration order: name, name span, whole span and
  optional bound as an existing structured `ParsedTypeSurface`. Retain the
  distinction between no written bound and an explicit bound.
- Parsed applied mixins as structured type surfaces, with their argument lists
  and original source spans. Add only what generated-mixin validation needs;
  implementing interface closure is not part of this decision.
- The resolver and driver preserve these facts into class IR. Lower bounds
  with the owning class binder scope available, including references to other
  parameters and recursive bounds.
- Preserve all existing raw-source/span contracts. Do not store synthesized
  text in fields documented as exact source.
- Class binders must win over same-spelled ordinary/builtin type names in
  their lexical scope. Function-local binders must not be mistaken for class
  binders. Do not infer bindings by matching arbitrary source substrings.

This is not a request for a general Dart type checker. Generated declarations
can keep the source binder names and let Dart instantiate typed helper
signatures. Any required substitution uses shared structured facts, not
per-plugin source rewriting.

## Emission contract

Generate each mixin with the source parameter list and bounds, and use the
parameterized class type at every typed reference. The shared emitter owns
mixin declarations; a plugin must not encode `<T>` into `class.name`.

For example, distinguish:

- Declaration: `Box<T extends num>`.
- Use: `Box<T>`.
- Named constructor call: `Box<T>.named(...)`.

All generated helper declarations must introduce their own required binders.
Copy interfaces, implementations, callback receiver types, casts and return
types must carry them consistently. Allocate generated result binders against
class parameter names: a user parameter named `$Res` cannot collide with the
copy helper's result parameter. Reuse the existing name allocator.

Nested copying must instantiate the nested model's helper with its actual
arguments, rather than dropping fields such as `Box<int>` from the nested-copy
plan. Preserve nullable nested-copy behavior and cross-file ownership.
Recursive/dependent bounds remain bounds, not use-site argument text.

Keep helper privacy at the declaring library boundary. Replacing an imported
model as a field value must stay typed; a parent must not reference another
library's private copy-helper class. A new cross-library chained-copy API is
not implied by adding generic arguments and would need a separate contract.

Keep existing constructor selection and private named-label behavior. Generic
support is not permission to choose a different constructor or rename fields.

## Null and omission are separate requirements

`T` is not necessarily non-nullable merely because its spelling lacks `?`.
For a field declared as unbounded `T`:

- `Box<int>(1).copyWith()` retains `1`.
- `Box<int>(1).copyWith(value: null)` retains the existing non-nullable-field
  null-as-omission behavior.
- `Box<String?>('before').copyWith()` retains `'before'`.
- `Box<String?>('before').copyWith(value: null)` clears the value.
- A field of type `List<T?>` remains a non-nullable list even though its
  elements are nullable.

Reuse the private sentinel class already emitted by copy generation, not a
plain canonical `const Object()` which callers could supply as a real value.
For an unbounded direct `T`, the language prototype used this decision shape:

```dart
identical(value, unset) || (value == null && null is! T)
    ? self.value
    : value as T
```

That expression is prototype evidence, not a prescription to apply it to
every field. The implementation must distinguish explicit nullable types,
non-nullable outer containers, type variables/bounds and compound nullable
types such as `FutureOr<T>`. Preserve existing behavior for non-generic
models. A test of `TypeIr::is_nullable()` alone cannot establish the effective
null behavior of a type variable.

## Where the change reaches

| Surface | Required work |
| :--- | :--- |
| Parser surface/backend | Ordered binder/bound and applied-mixin extraction, exact source/spans and grammar fixtures. |
| Resolver/driver/IR | Class scope and lowering hand-off; update constructors of these facts, cache/analysis serialization and audits where applicable. |
| Shared emission/validation | Typed mixin declarations, declaration/use rendering and source-located invalid-mixin diagnostics before output is written. |
| Derive | Copy helper binders, constructor calls, nullable type-variable handling, nested copies, equality, debug and validation typed receivers. |
| Other plugins | Audit every class-name-as-type emission and capability check; do not assume the shared mixin fix makes serializers, routes, state, HTTP or DB generic-safe. |
| Docs/examples/SDK gates | Fresh traditional/primary consumers, exact generated snapshots, failure preservation and executable public-API examples. |

`dust_parser_dart_ts/src/classes/class_decl.rs`,
`dust_resolver/src/result.rs`, `dust_driver/src/lower/members.rs`,
`dust_ir/src/class.rs`, `dust_emitter/src/emit.rs`, and
`dust_plugin_derive/src/features/clone_copy_with*` (all under `crates/`).
Copy constructor targets also come from derive's `features/writer.rs`.

## Staged acceptance

1. Add the structured facts and exact lowering contracts. Cover traditional
   and primary headers, multiple/recursive/dependent bounds, shadowed names,
   written mixins and argument order. Existing non-generic facts/output stay
   unchanged.
2. Implement typed derive generation, not a generic-class rejection. Compile
   and execute replacement/omission/null cases, named/private constructors,
   nested copies, binder-name collisions and equality/debug/validation.
3. Add real SDK consumers and relevant Flutter examples. Minimum/latest Dart
   exercise traditional syntax; primary syntax runs only on a compatible
   language version. Test negative replacement types and missing mixin
   arguments, and preserve previous output/cache on diagnostic failure.
4. Audit integration surfaces with concrete instantiations. Generic JSON
   fields already require custom codecs under the existing
   [serde contract](../usage/serde.md#supported-types); this proposal does not
   invent a generic decoder-callback API. SQL validation cannot infer a column
   type from an unconstrained `T` or a broad `num` bound. Document and test each
   feature's actual capabilities; any additional public API needs its own
   reviewed design. A blanket generic rejection is not completion of #93.

Before a focused implementation stage is ready: exact tests, changed-code
coverage with its scope stated, full sequential local lint/test gates,
fresh SDK analysis/execution and unchanged-output comparisons must pass.
No automatic merges, version bumps, releases or remote CI dispatch.

## Evidence and limits

A local language spike used independently resolved Dart packages with
recommended lints and strict casts, inference and raw-type analysis enabled:

- Dart 3.6.0 traditional declarations: fatal-info analysis and 12 tests passed.
- Dart 3.13.5 traditional declarations: the same checks and 12 tests passed.
- Dart 3.13.5 primary declarations: fatal-info analysis and 12 tests passed,
  including named, recursive-bound and dependent-bound primary headers.
- Four negative kernel-compilation probes failed for the expected type/member
  error on both SDKs: wrong replacement type, erased return assignment,
  omitted generic mixin arguments, and an extension declaring `toString`.

The tests included private-sentinel identity, nullable and non-nullable
instantiations of unbounded `T`, `Object?`, `dynamic`, `Null`, nested nullable
list elements and the extension-only dynamic-dispatch failure. The bound
probe used `String` satisfying `Comparable<String>`, not the invalid assumption
that `int` satisfies `Comparable<int>`.

These were **handwritten prototypes**, not Dust-generated output or permanent
regressions. They prove the proposed language shapes are viable and rule out
specific alternatives. They do not prove parser extraction, nested generic
copy generation, source preservation, every nullability shape, Flutter/native
platform execution or overall primary-constructor support. The user approved
this design; parser facts now survive resolution and class IR/lowering with
ordered bounds, mixin arguments and original spans. Scoped lowering distinguishes
class binders from builtin types, including nested types and constructor/member
signatures. Shared mixin declarations now render the owning parameters/bounds,
and invalid generated-mixin applications produce source-located diagnostics.
Typed copy helpers now retain class arguments/bounds, constructor selection,
equality and debug self types. Real generated traditional and primary consumers
exercise nullable type arguments, nullable aliases, `FutureOr<T>`, records,
generic callbacks, dependent/recursive bounds, result-binder collisions,
same-library nested helpers and typed imported replacements. Imported nested
helpers stay private; they are not a cross-library chaining API. Compiler-negative
checks reject wrong replacement/result types and imported helper access.
Core references for copy/equality/debug now use private library aliases only
where source binders or members shadow `String`, `Object`, `bool`, `int`,
`identical` or `pragma`. Names are allocated against library declarations,
class binders, fields and methods. Receiver/operand locals avoid class binders;
qualified runtime-type access avoids a binder named `runtimeType`. Opaque
function/record source and handwritten mixin arguments are not renamed.
Whole-output traditional/primary contracts and isolated real SDK consumers
cover these cases, including empty models, private generic collection helpers
and nullable nested getters. The SDK probe records intentional name-style
infos from these unusual binders, but rejects warnings, errors and every
unrelated lint; it does not add suppressions.

Parameters matching generated member names (`copyWith`, `toString`, `hashCode`)
still conflict with declarations in the generated mixin. This was reproduced
with real generation/kernel compilation and is tracked in
[#103](https://github.com/dustcodegen/dust/issues/103). Safely renaming a generated
binder may need additional structured substitution facts, not rewriting opaque
source. Integration capability checks also remain unfinished under #93. Neither design approval nor
the scoped copy tests establish general generic model support.

Generic validation now uses typed receivers and private static helper methods
that declare the owning parameters and bounds. Generic candidate nullability is
normalized by a private nullable typedef, not guessed from a field's spelling.
Required/null/custom/nested rules retain actual arguments, including aliases,
`FutureOr<T>`, records and generic function values. Runtime/core references and
helper locals avoid captured class binders. Receiver-free concrete Flutter input
validators keep their ordinary tearoff API; must-match helpers infer parameters
from a typed model receiver. Ordinary non-generic output stays unchanged.
The isolated [validation fixtures](../../fixtures/generic_validation) exercise
traditional and primary headers, runtime behavior and expected compiler errors
for a wrong private-helper receiver/candidate. These are scoped tests, not
general bound/interface resolution or generic support in every plugin.
Typed nested trait constructors such as `Validate<Object?>()` now retain
separate parser-owned short names and prefixes; applied type arguments and
qualifier trivia stay in raw source, not catalog lookup. The validation fixtures
exercise prefixed/unprefixed typed traits, including nested generic arguments.
Scoped namespace tests reject ambiguous/hidden/deferred or foreign ownership
without treating type-argument identifiers as qualifiers. These supplied-graph
tests are not #114's production namespace loader. Tracks
[#125](https://github.com/dustcodegen/dust/issues/125).

The SerDe capability audit now distinguishes known class parameters from SDK
scalars, containers and local/workspace JSON-capable types, including nested
collection elements/values. Such fields require explicit mapping under the
existing codec contract; no conversion is inferred from bounds. The diagnostic
retains the field source location, and rejected input preserves prior output and
cache. Qualified external names and concrete fields are not blanket-rejected.
This guard is [#129](https://github.com/dustcodegen/dust/issues/129), separate from
typed helper emission under [#128](https://github.com/dustcodegen/dust/issues/128).
Ordinary generic SerDe helpers, wrappers and public directional codecs now retain
class parameters/bounds, applied receiver/result types and constructor arguments.
Shared name allocation protects core/runtime references and generated locals
without renaming source binders. Where private JSON aliases would leak into a
public signature, a private implementation base preserves the public codec API.
Non-generic output remains byte-identical. Three complete generated snapshots
cover concrete fields, collections, codecs, defaults, strict keys and captured
names; real traditional/primary SDK probes execute runtime contracts and reject
four wrong receiver/result/bound uses per consumer.

This does not establish general generic SerDe readiness. Applied superclass facts
and inherited field substitution are implemented under
[#133](https://github.com/dustcodegen/dust/issues/133): parser/resolver/IR retain
applied types and source spans. Parent identities use syntax identifiers, never
qualifier/argument trivia. Raw type source stays unchanged. Shared lowering substitutes proven local
parent arguments simultaneously through nested/nullability shapes and multiple
levels. Source binders and original field locations remain intact. Child
overrides retain field order; super-formals infer the effective field type.
Raw or wrong-arity applications and substitutions inside opaque function/record
types fail clearly, rather than guessing bounds or rewriting source. Whole opaque
types can still be passed unchanged as actual arguments. Cached ancestor errors
propagate to generated descendants and preserve existing output/cache; unrelated
unused classes do not block a valid model. The permanent
[inheritance fixtures](../../fixtures/generic_inheritance) cover traditional and
primary concrete children, named super-formals, nested/reordered/dependent types,
callback overrides, named construction and inherited validation/JSON metadata.
The SDK gate requires complete generated snapshots, runtime/form behavior,
generated-line coverage and seven intended compiler failures per consumer.
Legacy non-generic lint headers are retained; strict language checks are not
relaxed. Intentional explicit-override style infos are recorded, not suppressed.
Imported parent/alias expansion and general opaque substitution remain outside
this proven scope. Empty-rule non-generic validation emits an existing unused
receiver warning, tracked separately in [#137](https://github.com/dustcodegen/dust/issues/137).
Structured redirect targets, generic sealed dispatch and synthesized variants are
implemented under [#134](https://github.com/dustcodegen/dust/issues/134), with final
acceptance still in progress. Parser/resolver/IR retain target types, optional
constructor identifiers and original spans, separately from declaration names.
Grammar type-path identifiers remain structured too. The resolver distinguishes
an unapplied `Class.named` target from a declared `prefix.Class` import without
mutating parser surfaces, using source identifier spans and import-prefix facts.
Shared structural substitution proves local ancestor applications; missing targets
retain only a complete permutation of the owner's source binders and bounds.
No source-string rewriting, imported-owner guessing or generic decoder callbacks
are added. Typed tagged/adjacent/untagged helpers protect runtime references and
locals. A named redirect differing from ordinary leaf codec selection receives a
private constructor-specific payload helper; ordinary selection stays unchanged.
Generic dispatch has an explicit unknown-subtype guard because Dart's exhaustiveness
analysis cannot prove every dependent generic pattern. Factory field metadata uses
the same annotation binding/normalization as handwritten fields. Generated public
factories allocate a documented public JSON payload alias only when private core
aliases would otherwise leak through their signatures. Non-generic snapshots remain
unchanged. Five full [sealed contracts](../../fixtures/generic_sealed) exercise
traditional and primary source, concrete/custom-codec fields, phantom/reordered/
dependent arguments, wire defaults/aliases, strict keys, collision binders and
unapplied non-generic named redirects.
They do not certify every constructor shape: independent required/optional parameter
facts and faithful omitted-variant grouping remain in
[#138](https://github.com/dustcodegen/dust/issues/138). Generic integration and overall
primary-constructor support remain incomplete until their remaining gates pass.

Explicit generic function-type classification is covered by
[#99](https://github.com/dustcodegen/dust/issues/99) /
[PR #100](https://github.com/dustcodegen/dust/pull/100), also applied to this draft.
Parser/resolver/driver regressions preserve `Function<T>(...)` signatures and
their local binders without rewriting source. The generated non-generic callback
example exercises omission, replacement and null clearing; it is not generic
class acceptance. Shorthand callback formals and their effective-type facts
remain separately pending in #92.

The generic-mixin driver regression exposed a cache-persistence defect, fixed
separately in [#101 / PR #102](https://github.com/dustcodegen/dust/pull/102) and
applied to this draft. Rejected mixin arguments preserve the affected library's
previous generated output and cache entry in build/check, for traditional and
primary headers and both fail-fast modes. Other valid libraries can still update;
this is not a workspace-wide atomic build. Assembly and diagnostic tests are not
substitutes for the remaining typed derive acceptance.
