## Check source changes without publishing

The manual workflow defaults to `publish=false`: it checks the exact selected
ref with formatting, Clippy, Rust workspace tests and release/installer gate tests.
Binary builds and publication are skipped. For example:

```sh
gh workflow run rust-release.yml --repo dustcodegen/dust --ref YOUR_BRANCH -f publish=false
```

Only explicitly selecting `publish=true` builds the pinned original release tag,
not the selected branch. The existing published release cannot be overwritten.
Current source fixes the upgrade destination to `dustcodegen/dust`; shipping that
change in a new binary release is separate work and is not part of this rebuild.
